# Royal Zen Living 社媒 Agent 工作台

这是面向比利时市场的社媒运营工作台 V2.0 原型、开发方案和完整参考归档。

## 入口

- `index.html`：可直接在浏览器打开的工作台 demo。
- `开发方案_社媒Agent工作台.html`：给产品、运营和开发人员看的说明书，可打印为 PDF。
- `开发方案_社媒Agent工作台.pdf`：HTML 转换的 PDF 版本。

## 工作流

选题与情报 → 平台内容设计（AI 起草、人工定稿）→ 生产任务（外部出片、结果回传）→ 发布与追溯 → 复盘回流。

## 当前原型重点

- 五步流程固定，只有当前步骤高亮。
- 平台设计内部完成人工定稿，未定稿不能生产。
- 创建生产工单后任务进入列表；视频在即梦或代码工具中外部生成，再登记成片结果。
- 发布页同时提供排期看板和全量台账，并记录已发布或具体卡点。
- 所有任务均可索引到复盘；复盘支持单条录入、平台 CSV、T+1/T+7/T+30 和选题回流。
- 台账与复盘索引支持标题或 Content ID 搜索，默认最近 10 条并可展开全部。

## 参考资料

- `参考技能/dreamina-canvas-cli`：即梦路线的工作方法与参考文档。
- `参考技能/existing-skills`：从旧版工作台迁移到新工作台的技能摘要。
- `参考项目/旧版工作台`：原有社媒内容生产工作台，作为迁移和对照材料。

## 一期最小 MVP

一期已从静态 Demo 升级为本地可运行工作台：

- 选题卡、平台版本、人工定稿、生产工单、外部交付、发布记录和数据快照可持久化。
- 生产路线严格限制为 `即梦路线`、`纯代码路线`。
- 工作台不生成图片、不渲染视频，只记录外部制作任务和交付结果。
- 未人工定稿不能创建生产工单。
- 成片未验收不能进入待发布或已发布。
- 发布数据支持手工录入和 CSV 导入，并区分 T+1、T+7、T+30。

## 二期生产协同

- 首页行动队列支持新建、编辑、负责人、优先级、截止日期和状态。
- Facebook / Instagram、Pinterest、YouTube、TikTok 账号状态可维护并持久化。
- 生产工单支持待开始、制作中、生产受阻、待验收、修改中、已验收和已取消。
- 外部成片支持多版本登记，每个版本保留独立链接、交付说明和验收记录。
- 验收可以通过或退回修改；退回后保留旧版本，等待新版本再次交付。
- 已验收工单不可回退，未验收交付仍然不能进入发布。

## 三期发布与复盘

- 每次发布状态变化写入独立 `Publication` 历史，不再只覆盖当前状态。
- 标记“已发布”时必须填写真实平台链接。
- 每次手工或 CSV 数据导入必须填写数据来源和来源日期。
- T+1、T+7、T+30 以独立 `MetricSnapshot` 追加保存，保留每次导入批次。
- 系统只使用带来源的 T+7 同口径数据生成建议。
- 建议自动包含来源、样本、基准、数字、建议动作和待验证变量。
- 建议缺少任一证据要素时禁止采纳；运营数据不会自动改变已确认策略。

## 四期人员留痕与操作记录

- 不设置原型和开发方案未定义的管理员、运营、审核、只读角色层级。
- 当前参与人员仅采用原型明确出现的“社媒运营负责人”和“业务负责人”。
- 所有关键修改自动记录操作者、动作、对象、摘要和时间。
- 人工定稿人和交付验收人继续在对应业务表单中单独填写，不由角色系统代替。
- 已登记的参与人员可以查看操作记录并导出完整 JSON 备份；导出动作本身也进入操作记录。

## 五期 MVP 完整度补齐

- 选题卡补齐参考来源、目标平台和待验证变量。
- 平台内容版本补齐时长、标题、正文、标签、CTA、语言和封面要求，并支持保存后查看、编辑和进入人工定稿。
- 人工定稿按具体平台版本记录脚本、分镜、字幕、封面文案、审核人和冻结版本。
- 素材建立独立 Asset 记录，登记时在“外部文件链接”和“上传到工作台本地”之间二选一。
- 本地文件保存到 `data/uploads/<Content ID>/`，单文件上限 500MB；只新增版本，不提供删除或覆盖。
- 素材验收结果与交付版本关联；工作台仍不生成图片、不渲染视频。
- AI 情报雷达按钮打开方案中已有的外部入口，不在本地伪造情报结果。
- 首页“调整队列”提供现有任务上移、下移和顺序持久化；新建任务仍由独立按钮处理。
- 行动任务编辑页提供二次确认的软删除；删除后退出首页队列，但保留原任务、删除人、删除时间和操作记录。

## 运行

需要 Node.js 18 或更高版本。在当前目录运行：

```powershell
npm start
```

然后打开 <http://127.0.0.1:8899>。业务数据保存在 `data/store.json`；第一次启动会自动从 `data/seed.json` 初始化。

运行自动化验收：

```powershell
npm test
```

不要再直接双击 `index.html`，直接打开文件时无法使用持久化接口。

开发方案的 PDF 由同目录 HTML 打印生成。正式开发时，建议先按验收标准走通一条完整内容，再进入平台接口和自动化发布阶段。

## 第 4 步与第 5 步的连接

Demo 使用一套共享的内容台账。第 4 步用 Content ID 管理排期、素材、文案、发布状态、平台链接和卡点；第 5 步保留全部任务索引，并按 T+N 快照展示可比较数据。两个页面可按同一 Content ID 双向定位。
