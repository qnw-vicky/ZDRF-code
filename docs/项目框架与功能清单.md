# 社媒 Agent 工作台：项目框架与功能清单

> 项目：Royal Zen Living 社媒 Agent 工作台  
> 当前版本：`1.4.2-phase5`  
> 文档依据：当前项目代码、数据契约、工作流定义及自动化测试  
> 更新日期：2026-11-16

## 1. 项目定位

本项目是面向社媒内容运营的本地工作台，用于记录和推进以下完整业务链路：

**选题与情报 → 平台内容设计 → 人工定稿 → 外部生产 → 素材验收 → 发布追溯 → 数据复盘 → 回流下一轮选题**

工作台负责下任务、保存版本、登记结果、人工验收和过程追溯，不直接执行图片或视频制作。

生产路线严格限定为：

1. `即梦路线`
2. `纯代码路线`

视频和图文均在外部工具中制作，完成后将文件链接或实际文件登记回工作台。

## 2. 系统边界

### 2.1 工作台负责

- 管理行动任务和账号准备状态。
- 保存选题卡与平台内容版本。
- 记录人工定稿版本。
- 下发外部生产工单。
- 登记外部制作结果和素材版本。
- 对交付结果进行人工验收。
- 保存发布记录、平台链接和卡点。
- 导入发布后的指标数据。
- 基于同口径数据生成带证据的复盘建议。
- 保存操作者和关键操作记录。

### 2.2 工作台明确不负责

- 不调用图像模型生成图片。
- 不使用 Remotion 或其他渲染器制作视频。
- 不在工作台内部完成图文或视频生产。
- 不自动登录或操作社媒平台。
- 不自动发布内容。
- 不因运营数据自动修改已经确认的账号策略。

以上属于已经确认的产品边界，不应当作为程序缺陷或漏做功能处理。

## 3. 技术架构

当前版本采用适合本地 MVP 的轻量单体架构。

```text
浏览器界面
index.html + app.js + CSS
        │
        │ HTTP / JSON API
        ▼
Node.js 本地服务
server.js
        │
        ├── 业务数据：data/store.json
        ├── 初始数据：data/seed.json
        ├── 本地素材：data/uploads/<Content ID>/
        └── 规则定义：data.contract.json / workspace.policy.json

外部制作工具、社媒平台、平台数据后台
        │
        └── 当前通过人工操作、链接登记、文件上传或 CSV 导入与工作台衔接
```

### 3.1 前端

- 技术：原生 HTML、CSS、JavaScript。
- 入口：`index.html`。
- 主要交互：`app.js`。
- 形式：单页面工作台，通过板块切换展示五步业务流程。
- 当前阶段提示会根据所在板块动态更新。

### 3.2 后端

- 技术：Node.js 18+ 原生 HTTP 服务。
- 入口：`server.js`。
- 默认地址：`http://127.0.0.1:8899`。
- 主要职责：静态页面服务、业务 API、数据校验、文件上传、审计记录和 JSON 导出。

### 3.3 数据存储

- 主业务数据保存在 `data/store.json`。
- 第一次启动时从 `data/seed.json` 初始化。
- 本地上传素材保存在 `data/uploads/<Content ID>/`。
- 单个本地文件上限为 500MB。
- 当前没有使用 MySQL、PostgreSQL、MongoDB 或云对象存储。

### 3.4 规则与契约

- `data.contract.json`：定义业务实体、必要字段和业务约束。
- `workspace.policy.json`：定义人工门禁、执行边界、素材策略和证据规则。
- `workflows/mvp-workflow.json`：定义完整业务节点及节点输出。
- `project.manifest.json`：记录项目入口、版本和关键配置文件。

## 4. 核心业务对象

| 对象 | 作用 |
| --- | --- |
| Participant | 记录当前操作者，目前只有“社媒运营负责人”和“业务负责人” |
| AuditLog | 记录关键操作的操作者、对象、动作和时间 |
| ActionTask | 首页行动队列中的执行任务 |
| Account | Facebook、Instagram、Pinterest、YouTube、TikTok 等账号准备状态 |
| Idea | 选题、来源、客户问题、展示价值和待验证变量 |
| PlatformVersion | 同一选题针对不同平台形成的内容版本 |
| Review | 脚本、分镜、字幕、封面文案的人工定稿记录 |
| ProductionTask | 下发给即梦路线或纯代码路线的外部生产工单 |
| Asset | 外部链接或本地上传的素材记录 |
| Delivery | 外部制作结果及其验收状态 |
| Publication | 每次发布状态变化形成的历史记录 |
| MetricSnapshot | T+1、T+7、T+30 指标快照 |
| ImportBatch | CSV 数据导入批次 |
| Insight | 带来源、样本、基准和数字的复盘建议 |

所有业务链路以 `Content ID` 作为主要追溯标识。

## 5. 已实现功能

### 5.1 总览与行动队列

- 展示待推进任务、账号连接情况、待发布内容和复盘时间。
- 新建和编辑行动任务。
- 记录负责人、优先级、截止日期、状态和业务说明。
- 支持行动任务上移、下移和顺序持久化。
- 支持行动任务软删除。
- 删除前进行二次确认。
- 删除后任务退出行动队列，但保留原任务、删除人、删除时间和操作记录。
- 账号列表逐条编辑状态、负责人和备注。

### 5.2 选题与情报

- 保存选题主题、参考来源、客户问题和展示价值。
- 保存目标平台和待验证变量。
- 形成可继续进入平台设计的选题卡。
- 情报雷达按钮打开既有外部入口，本地工作台不伪造情报结果。

### 5.3 平台内容设计

- 为不同平台建立独立内容版本。
- 保存内容形式、画幅、时长、语言、标题、正文、标签、CTA、封面要求和平台版表达。
- 保存后可继续查看和编辑。
- 支持脚本、分镜、字幕和封面文案的人工定稿。
- 人工定稿记录具体平台版本、审核人、冻结版本和定稿时间。
- 未完成人工定稿时禁止创建生产工单。

### 5.4 生产任务与素材

- 生产路线只允许选择“即梦路线”或“纯代码路线”。
- 创建生产工单并记录 Content ID、标题、路线、负责人、画幅、交付日期和交付清单。
- 支持生产工单状态维护。
- 支持登记多个外部交付版本。
- 每个交付版本独立保留文件、说明和验收记录。
- 素材保存方式支持二选一：
  - 登记外部文件链接。
  - 上传并保存到工作台本地。
- 本地文件单文件上限为 500MB。
- 支持交付验收通过或退回修改。
- 退回修改后保留原版本，等待登记新版本。
- 已验收工单不可回退。
- 未验收素材不能进入待发布或已发布状态。

### 5.5 发布与追溯

- 展示发布排期和内容台账。
- 可按 Content ID 或标题搜索。
- 记录发布平台、计划或实际日期、发布状态、平台链接和卡点。
- 每次发布状态变化追加一条独立 Publication 历史。
- 标记“已发布”时必须填写真实平台链接。
- 支持从台账直接定位到复盘数据。

### 5.6 数据复盘

- 支持手动录入单条内容指标。
- 支持上传平台 CSV 批量导入。
- 每次导入必须保存真实来源和来源日期。
- 指标按 T+1、T+7、T+30 独立追加保存。
- 保存曝光、播放、完播率、互动数和点击数。
- 只允许为已发布内容写入指标。
- 使用带来源的 T+7 同口径数据生成复盘建议。
- 建议包含来源、样本、基准、数字、建议动作和待验证变量。
- 缺少证据要素的建议不能被采纳。
- 采纳建议后可回流为下一轮选题输入。

### 5.7 操作者与审计

- 当前参与人员只有“社媒运营负责人”和“业务负责人”。
- 两者目前没有功能权限差异，只用于标记当前操作者。
- 关键修改必须绑定已登记的操作者。
- 关键操作自动写入操作记录。
- 支持查看操作记录。
- 支持导出完整 JSON 数据备份。
- 数据导出动作本身也写入操作记录。
- 未引入原型中没有定义的管理员、审核、只读等角色层级。

### 5.8 测试与运行

- 提供 13 项 Node.js 自动化测试。
- 已覆盖参与人员校验、选题、平台内容版本、行动队列、软删除、排序、人工定稿门禁、生产路线、素材存储、交付验收、发布指标、复盘建议和审计导出。
- 测试使用临时数据文件，不应修改正式的 `data/store.json`。

## 6. 未实现功能

以下功能当前尚未实现；如要增加，应先确认是否纳入下一阶段范围。

### 6.1 外部自动化接入

- 未接入即梦或纯代码制作工具的任务 API。
- 未实现外部生产完成后的自动回调。
- 未接入 Facebook、Instagram、Pinterest、YouTube、TikTok 等平台的发布 API。
- 未实现自动排期发布、自动重试和发布结果自动回传。
- 未接入平台官方数据 API 自动取数。
- 当前平台数据依赖手动录入或 CSV 导入。
- 情报雷达当前只是打开外部入口，没有把情报结果自动同步回本地选题卡。

### 6.2 AI 能力接入

- 未接入大模型自动生成选题卡、平台文案、脚本或分镜。
- 当前复盘建议由本地规则基于 T+7 数据生成，不是外部大模型推理。
- 未实现提示词版本管理、模型调用记录、费用统计或模型结果评测。

### 6.3 用户、权限与协作

- 未实现账号登录、密码、单点登录或企业身份认证。
- 未实现基于角色的权限控制。
- “社媒运营负责人”和“业务负责人”目前只是操作者标识，不限制功能。
- 未实现多人同时编辑冲突处理、评论、@提醒、站内通知或审批消息推送。

### 6.4 账号与资源管理

- 当前账号为预置记录，只支持逐条修改状态、负责人和备注。
- 未实现新增平台账号、删除账号或管理同一平台的多个账号。
- 未实现 OAuth 授权、Token 管理和账号连接状态自动检测。

### 6.5 文件与素材管理

- 未实现本地素材删除、覆盖或回收站。
- 未实现云对象存储、断点续传、文件去重、病毒扫描或自动转码。
- 未实现素材缩略图、视频在线播放、图片预览和高级素材检索。
- 未实现文件生命周期和空间配额管理。

### 6.6 任务与业务记录管理

- 只有行动任务支持软删除。
- 生产工单、素材、交付版本和发布记录不支持删除。
- 未实现批量编辑、批量归档或批量导入任务。
- 未实现日历提醒、逾期通知或自动催办。

### 6.7 生产级部署能力

- 当前使用本地 JSON 文件，不是生产级数据库。
- 未实现数据库事务、并发写入保护和数据迁移工具。
- 未实现云端部署、HTTPS、域名、容器化和自动发布流水线。
- 未实现定时自动备份、备份恢复界面、监控告警和运行日志管理。
- 未进行高并发、超大文件、长时间运行或灾难恢复测试。

## 7. 当前主要业务门禁

1. 所有关键修改必须有已登记的当前操作者。
2. 平台内容未人工定稿，不能创建生产工单。
3. 生产工单路线只能是即梦路线或纯代码路线。
4. 外部交付未验收，不能进入待发布或已发布状态。
5. 标记已发布时必须填写平台链接。
6. 只有已发布内容可以录入发布指标。
7. 复盘建议缺少来源、样本、基准或数字时不能采纳。
8. 运营数据只能优化内容组合和执行方式，不能自动替换已确认策略。

## 9. 本地运行

环境要求：Node.js 18 或更高版本。

```powershell
cd "D:\中道瑞丰\agent工作台\agent项目"
npm start
```

浏览器访问：

```text
http://127.0.0.1:8899
```

运行自动化测试：

```powershell
npm test
```

不要直接双击 `index.html` 使用工作台；直接打开静态文件时无法连接持久化 API。

## 10. 后续开发原则

- 不增加未经确认的生产路线。
- 不把工作台改造成图片或视频制作工具。
- 新功能必须继续以 Content ID 保持全过程追溯。
- 自动化接入前先保留人工门禁和可回退机制。
- 已发布记录、指标来源和操作记录必须可追溯。
- 任何新增角色、权限、删除能力或外部自动化，都应在开发前单独确认范围。
